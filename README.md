# RDA Test Fit Checker

כלי עבודה דו-פאנלי לבדיקת תוכניות Test Fit — מעלים תוכנית, מקבלים ניתוח על גבי התכנית.
עובד לגמרי בדפדפן (client-side), בלי שרת ובלי העלאת קבצים לשום מקום.

**ריפו פרטי.** אין לפרסם אותו ואין להעלות לתוכו דאטה של לקוחות (תוכניות, כתובות, תקציבים, שמות פרויקטים).

---

## הרצה

הכלי דורש הגשה דרך `http://` (לא `file://`) כי pdf.js עובד עם Web Worker.

```powershell
cd rda-testfit-checker
python -m http.server 7432
```

ואז לפתוח <http://localhost:7432/>

## מבנה

| נתיב | מה זה |
|---|---|
| `index.html` | הכלי כולו — HTML/CSS/JS בקובץ אחד, כולל קוד ה-EXPORT |
| `lib/pdf.min.js` | pdf.js מקומי (לא CDN) |
| `lib/pdf.worker.min.js` | ה-worker של pdf.js — הנתיב מוגדר ב-`pdfjsLib.GlobalWorkerOptions.workerSrc` |

## פורמטים נתמכים

| קלט | מה קורה |
|---|---|
| PDF עם שכבת טקסט | ניתוח אוטומטי מלא — פענוח תגיות חדרים, טבלת חדרים, בדיקות קומתיות, סמנים על התכנית |
| PDF שטוח / סרוק, PNG, JPG | מצב ידני — התכנית נטענת כתמונה, כל הכלים הידניים פעילים (סימבולים, קווי מידה עם כיול, הערות) |
| JSON | פרוגרמה + QA; אם יש בו `review` ותכנית טעונה — משוחזרים סימבולים, מידות וצ׳קליסט |
| DWG / RVT | לא נתמך — פורמט בינארי סגור. הכלי מציג הוראות ייצוא (AutoCAD: Plot → DWG To PDF · Revit: File → Export → PDF) |

## יכולות

- **כללי ברזל** — מידות במטרים, קווי מידה אורך/רוחב, כניסה+יציאה, ארונות חשמל+תקשורת. נבדקים אוטומטית מהטקסט, ואם חסר — מסומנים ידנית ע״י הצבת סימבול.
- **מחסן סימבולים** — 18 סימבולים ב-3 קבוצות, drag & drop. קואורדינטות נשמרות מנורמלות (0..1) ושורדות זום.
- **כלי מידה + כיול** — מכיילים קו אחד על מידה ידועה, וכל קו מידה אחריו מחושב אוטומטית במטרים.
- **פרוגרמה מ-JSON** — ממזג יעדים, בונה טבלת Δ מול המצוי. יש תבנית להורדה מתוך הכלי.
- **בדיקת חדרים מול הפרוגרמה (`schedule`)** — כשבקובץ הפרוגרמה יש `schedule`, כל חדר ברוויט מותאם לקוד שלו (למשל `FL01-MR-02` בשדה Number, והמחלקה בשדה Department). אם אין קוד, ההתאמה נעשית לפי סוג החדר (גם בשמות בעברית) ולפי המחלקה. מה שנשאר בלי התאמה משויך ידנית מתוך ההערה. לכל קוד נבדקים שטח מינימלי, מקומות ישיבה, עמדות לפי מחלקה והתאמת Department. ברמת הקומה נבדקים כוח אדם (עמדות + משרדים סגורים), נטו מול ברוטו, חסרים, עודפים וקודים כפולים או לא מוכרים. סמיכויות "A ↔ B" נמדדות על קונטורי החדרים ומוצגות כהמלצה בלבד. מתוך טאב הפרוגרמה אפשר להוריד Excel עם הקודים להקלדה ברוויט. פרוגרמה בלי `schedule` עובדת בדיוק כמו קודם.
- **תקנים ודרישות (טאב "תקנים")** — כל דרישה עם המקור שלה: תקנות התכנון והבנייה, תוספת 2 (מעבר בדרך מוצא ≥ 110 ס״מ, פתח דלת ≥ 80, מרחק הליכה ופרוזדור ללא מוצא במשרדים, תפוסה 10 מ״ר לנפש ומספר דרכי מוצא), ת״י 1918 חלק 3.1 (דרך נגישה ≥ 130, משטח תפקוד, קיר בצד המנעול, שטח סיבוב Ø150, תא שירותים נגיש 150×200, כבש), ונוהג משרדי (כיסא–קיר) שמסומן במפורש כלא-חוק וניתן לדריסה דרך `rules.norms`. בתכנית מרוויט הרוחב של מסדרונות ותאי שירותים נגישים נבדק אוטומטית מהקונטור. בכל תכנית אחרת: **מידה חכמה**, לחיצה אחת בתוך חלל שנמדדת מקיר לקיר (אחרי כיול אחד), והפער מול התקן נרשם כהערה על התכנית.
- **EXPORT** — HTML עצמאי (~1.3MB) עם PNG מוטמע ו-state כ-JSON. ניתן להמשיך לערוך בו הערות וסימבולים, והדוח מתעדכן בלייב.

## קבצי דוגמה

`samples/` — דאטה בדויה בלבד, בלי שמות לקוחות:
- `sample_FL01_program.json` — פרוגרמה עם `schedule` (12 קודים) ו־`qa` עם סמיכויות.
- `sample_FL01_rooms.json` — ייצוא חדרים בפורמט המאקרו, ובו מקרי מבחן: תקין, שטח חסר, מקומות חסרים, אופן ספייס מפוצל, התאמה לפי סוג, קוד כפול, קוד לא מוכר, חדר לא מזוהה, וחדר חסר (מטבחון).

טוענים את ייצוא החדרים ואת הפרוגרמה, בכל סדר, דרך "העלה JSON".

## עדכון הריפו

עורכים **תמיד** את המאסטר: `D:\RDA - AI\RDA_TestFit_Checker.html`. ואז:

```powershell
& "D:\RDA - AI\sync-testfit.ps1" -Message "מה שהשתנה"
```

הסקריפט בודק שהמאסטר לא קטוע, מעתיק אותו לאתר המצגות ולריפו (כ-`index.html`), עושה קומיט ודוחף ל-`main`.
`-NoPush` עוצר לפני הדחיפה. אם אין שינויים הוא לא עושה כלום.

## הערות תחזוקה

- `intent: 'print'` ב-`page.render` הוא **חובה** — בלעדיו הרינדור נתקע בטאבים לא-נראים (rAF throttling).
- `renderBase()` מרנדר פעם אחת ל-offscreen canvas 2400px; `layout()` מצייר ממנו מוקטן. זום ו-resize לא מרנדרים PDF מחדש.
- קוד ה-export יושב ב-`<script type="text/plain" id="exportCSS">` / `id="exportJS"` כדי למנוע בעיות escaping. **אסור** להכניס `</script>` בתוכם.
- צבעי סטטוס: fail `#E1504B` · warn `#E38B00` · info `#0000FF` · ok `#16A34A`.
